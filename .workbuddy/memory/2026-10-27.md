## #8/#9/#10 端侧 AI 真机跑通（低配档实测完成）

**#8 编译 + #9 接线**：NDK 26.1.10909125 + CMake 3.22.1 装好，交叉编译 arm64-v8a 四个 `.so`（libllama 28MB / libggml / libggml-base / libggml-cpu），全部 `Align 0x4000`；`llama_cpp_dart 0.2.2` + `dependency_overrides {meta 1.15.0, ffi 2.1.3}`；`kOnDeviceLlmWired = true`。

**真机才暴露的三个坑（都已修，写进代码注释）**：
1. **`.so` 版本必须与 Dart 绑定同源** —— b11919 编的库一加载就 SIGSEGV（fault 0x104，`llama_model_loader`）；换 `llama.cpp 4ffc47cb2001e7d523f9ff525335bbe34b1a2858` 重编即通。这是本次最大时间黑洞。
2. **`mainGpu` 必须 -1** —— 包内 `ModelParams()` 默认 0，纯 CPU 构建下 llama.cpp 报 `invalid value for main_gpu: 0 (available devices: 0)` 并返回 null（表现为 loading 25ms 就 "Could not load model"，无更多日志）。同时 `nGpuLayers = 0`。
3. **模型必须放应用内部目录** —— `/storage/emulated/0/Android/data/...`（FUSE）加载卡死抛 `Disposed`；改 `getApplicationDocumentsDirectory()`，用 `adb push /sdcard/` + `run-as cp files/` 送进去。

**排障工具（保留在代码里）**：`LlamaDirectBackend`（主 isolate 直连）+ libc `open`/`dup2` 把 fd 2 重定向到 `app_flutter/llama_stderr.log`。包内 `verbose=true` 时日志只走默认 stderr、不进 logcat；`NativeCallable.listener` 异步投递会拿到已释放的 buffer（乱码），所以必须 dup2。

**#10 低配档实测（iPlay80Mini，3.74GB，Android 16，arm64-v8a，800×1340）**：
- 首 token **26.1–26.7s**；44 字 38.5s、71 字 41.7s（≈**1.7 tok/s**）
