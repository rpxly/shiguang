## 相簿归档方案：定稿为「物理移动」（参考 Slidebox）
- 现状问题：`organize_page._syncLocalAlbums` 用 `photoIdSet.contains(asset.id)` 取交集，只给「已入库照片」贴 id 标签，系统相册里有的照片会被丢弃；相簿状态存两份（Hive `album_photos_*` + MediaStore），导致计数虚高、删照片不清理、只增不减、同步后 0 张。
- 定稿方案：相簿 = 系统真实目录，App 不再存第二份 id 列表。移动走 `PhotoManager.editor.android.moveAssetsToPath`（Android 11+：`MediaStore.createWriteRequest` 一次授权 + 逐条 `UPDATE RELATIVE_PATH`），不复制字节、`_ID` 不变。
- 目录根从 `DCIM` 改为 **`Pictures/拾光/<相簿名>`**：Slidebox 官方 FAQ 证实 Android 相册就是 `Pictures/<album>` 文件夹；`DCIM` 易被 ROM 当相机胶卷忽略。
- Slidebox 可抄：两段式删除（先 app 内 trash 再永久删）、明确「不保留副本」、放弃双向跟随。
- 已落地（0.1 Spike）：新增 `lib/services/photo_move_service.dart`（ArchivePaths/MovableSources/MoveItemResult/MoveBatchResult/串行锁/逐条 relativePath 校验/findBucket/restore），新增 `lib/pages/archive_spike_page.dart`，设置页「应用」卡片加入口「本地归档验证」。
- 关键坑：photo_manager 的 writeHandler 是单实例，并发调 moveAssetsToPath 会互相覆盖 → service 内加串行队列；`moveAssetsToPath` 部分失败也返回 true，必须回查 relativePath；targetPath 需带尾斜杠与 MediaStore 惯例一致。
- 下一步：真机跑 Spike（Pictures/DCIM 各 20 张）验证 bucket 是否立刻可见，再决定 P1（Album.relativePath + 删 album_photos_ + 一次性批量流程）。
