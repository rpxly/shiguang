# 月刊模板系统修复计划

## 问题总结

用户反馈：导入点击无效、整体页面相当于废了（截图显示顶部栏+月份导航+概览头部正常，时光线区域有"4/12张"标题但条目全空白）。

## 根因分析（基于代码探索）

### 根因 1：`_loadAsync` 无异常保护，`_loading` 永久卡死（致命）

[f:\daima\ai-album\lib\pages\monthly_magazine_page.dart:384-413](file:///f:/daima/ai-album/lib/pages/monthly_magazine_page.dart#L384-L413)

```dart
Future<void> _loadAsync() async {
  setState(() => _loading = true);   // ← 设置 loading=true
  await Future.delayed(Duration.zero);
  if (!mounted) return;              // ← 若未 mounted 直接 return，_loading 永远 true
  final stored = widget.repository.getMagazinePages(_year, _month);
  _pages = stored.map(MagPage.fromJson).toList();  // ← MagPage.fromJson 若抛异常，_loading 永远 true
  _monthPhotos = _pages
      .map((p) => p.photoIds.first)        // ← photoIds 为空时 RangeError
      .map((id) => widget.repository.getPhoto(id))
      .whereType<Photo>()                   // ← getPhoto 返回 null 时静默丢弃
      .toList();
  // ... _imgSizeCache 加载也可能抛异常
  if (mounted) setState(() => _loading = false);  // ← 永远到不了这里
}
```

**MagPage.fromJson 的脆弱点** [L214](file:///f:/daima/ai-album/lib/pages/monthly_magazine_page.dart#L214)：
```dart
photoIds: (j['photoIds'] as List).cast<String>(),  // ← photoIds 为 null 时 cast 失败
```

**getMagazinePages 吞异常** [f:\daima\ai-album\lib\repository\local_repository.dart:175-185](file:///f:/daima/ai-album/lib/repository/local_repository.dart#L175-L185)：
```dart
try {
  final list = jsonDecode(stored);
  if (list is List) return list.cast<Map<String, dynamic>>();  // ← cast 失败被 catch 吞掉返回 []
} catch (_) {}
```

→ 一旦 JSON 数据有任何异常，`getMagazinePages` 返回 `[]`，`_pages` 为空，`_monthPhotos` 为空，页面显示空状态。

### 根因 2：`_buildTimelineEntry` 布局层级过深导致渲染失败（页面空白）

[f:\daima\ai-album\lib\pages\monthly_magazine_page.dart:1677-1784](file:///f:/daima/ai-album/lib/pages/monthly_magazine_page.dart#L1677-L1784)

当前嵌套：
```
IntrinsicHeight
└── Row
    ├── SizedBox(width:24) 时间线竖线
    └── Expanded
        └── Container
            └── ClipRRect
                └── Column
                    ├── RepaintBoundary
                    │   └── LayoutBuilder          ← LayoutBuilder 在 IntrinsicHeight 下会出问题
                    │       └── _renderSingleTemplate
                    │           └── Padding(margin)
                    │               └── Column
                    │                   ├── ClipRRect + SizedBox(height) + _imageArea
                    │                   └── Padding + Column + _metaLine + _captionText
                    └── Padding 操作按钮行
```

**关键问题**：`IntrinsicHeight` 要求子 widget 提供固有高度，但 `LayoutBuilder` 的子 widget 高度依赖父级约束，在 `IntrinsicHeight` 下形成循环依赖，导致 `RepaintBoundary` 内的模板区域高度塌陷为 0，视觉上就是空白。

### 根因 3：`_showImporter` 导入流程依赖 `_loadAsync` 重新加载

[f:\daima\ai-album\lib\pages\monthly_magazine_page.dart:747-822](file:///f:/daima/ai-album/lib/pages/monthly_magazine_page.dart#L747-L822)

```dart
// 循环导入每张图
for (final image in toImport) {
  // ... copy 文件、savePhoto、_pages.add(page)
  _getImageSize(destPath).then((s) {
    if (s != null && mounted) setState(() {});  // ← 异步回调
  });
}
_persist();
await _loadAsync();  // ← 这里会 _imgSizeCache.clear() 重新加载，且若抛异常导入看似失败
```

问题：
1. `_persist()` 后 `await _loadAsync()` 会清空 `_imgSizeCache` 重新加载，前面 `_getImageSize.then` 的加载白做
2. `_loadAsync` 抛异常时，导入的文件和 Photo 记录已写入，但 `_pages` 和 `_monthPhotos` 内存数据被清空，UI 显示空白
3. `_loading = true` 后若 `_loadAsync` 卡住，页面永久骨架屏

### 根因 4：`_monthPhotos` 与 `_pages` 数据不一致

[L392-396](file:///f:/daima/ai-album/lib/pages/monthly_magazine_page.dart#L392-L396)：`getPhoto(id)` 返回 null 时 `.whereType<Photo>()` 静默丢弃，导致 `_pages` 有 N 条但 `_monthPhotos` 可能少于 N 条，`_buildTimelineView` 遍历 `_monthPhotos` 渲染时漏掉条目。

## 修复方案

### 修复 1：`_loadAsync` 加异常保护，确保 `_loading` 一定能复位

**文件**：[f:\daima\ai-album\lib\pages\monthly_magazine_page.dart](file:///f:/daima/ai-album/lib/pages/monthly_magazine_page.dart)
**位置**：L384-413 `_loadAsync` 方法
**改法**：
- 整个方法体包 `try/finally`，`finally` 中 `if (mounted) setState(() => _loading = false)`
- `_pages = stored.map(MagPage.fromJson).toList()` 改为循环 + try-catch，单条解析失败跳过
- `.map((p) => p.photoIds.first)` 加 `photoIds.isNotEmpty` 防御
- `getPhoto(id)` 返回 null 时记录日志并从 `_pages` 中移除该 MagPage（保持一致性）

### 修复 2：`MagPage.fromJson` 加字段防御

**文件**：同上
**位置**：L200-244 `MagPage.fromJson`
**改法**：
- `photoIds: (j['photoIds'] as List?)?.cast<String>() ?? const []` —— 容忍 null
- 其他 `as` 转换保持现有 `as num?` / `as String?` 防御风格

### 修复 3：重构 `_buildTimelineEntry` 布局，去掉 `IntrinsicHeight` + `LayoutBuilder` 嵌套

**文件**：同上
**位置**：L1677-1784 `_buildTimelineEntry`
**改法**：
- 去掉最外层 `IntrinsicHeight`，改用 `Row` + `Stack` 实现时间线竖线（竖线用 `Positioned` 绝对定位，不依赖 IntrinsicHeight）
- 去掉模板区的 `LayoutBuilder`，改为在 `_buildTimelineEntry` 入口处用 `MediaQuery.of(context).size.width - AppSpacings.xl * 2 - 24 - 12`（屏幕宽 - 左右 padding - 时间线宽 - 间距）直接计算 `cardWidth`，传给 `_renderSingleTemplate`
- 简化层级为：`Row → [时间线 SizedBox, Expanded → Container → ClipRRect → Column → [RepaintBoundary(template), 操作按钮行]]`

新结构：
```
Row
├── SizedBox(width:24) 时间线竖线（用 Stack 画圆点+竖线，竖线高度用固定值如 200+按钮区高度）
└── Expanded
    └── Container
        └── ClipRRect
            └── Column
                ├── RepaintBoundary
                │   └── _renderSingleTemplate(cardWidth=计算值)  ← 直接渲染，无 LayoutBuilder
                └── Padding 操作按钮行
```

### 修复 4：`_getImageSize` 失败时写入占位尺寸，避免重复尝试

**文件**：同上
**位置**：L706-744 `_getImageSize`
**改法**：
- 文件不存在或解析失败时，写入 `_imgSizeCache[path] = _ImgSize(1, 1)`（占位尺寸，让 `_resolveImageHeight` 返回一个小的默认高度，而不是 minHeight=200）
- 或新增 `_imgSizeFailed` Set 记录失败 path，build 时跳过

### 修复 5：`_showImporter` 导入流程不依赖 `_loadAsync` 重新加载

**文件**：同上
**位置**：L747-822 `_showImporter`
**改法**：
- 导入循环中，每张图 copy + savePhoto + `_pages.add(page)` + `_monthPhotos.add(photo)` + `_getImageSize`（同步加入 `_imgSizeCache` 加载队列）
- 循环结束后 `_persist()` 持久化
- 直接 `setState(() => _loading = false)` 刷新 UI，不再调 `await _loadAsync()`
- 这样避免了清空缓存重新加载的开销，也避免了 `_loadAsync` 异常导致数据丢失

### 修复 6：`_monthPhotos` 与 `_pages` 一致性保证

**文件**：同上
**位置**：L392-396 `_loadAsync` 中
**改法**：
- `getPhoto(id)` 返回 null 时，从 `_pages` 中移除对应 MagPage（`_pages.removeWhere((p) => p.photoIds.contains(id))`）
- 循环结束后若 `_pages` 有变化，调 `_persist()` 修正存储

## 假设与决策

1. **不引入新的状态管理框架**：直接在现有 StatefulWidget 内修复，保持架构一致
2. **不改变数据存储格式**：MagPage.toJson / fromJson 的字段保持兼容，只加防御
3. **不改变 6 个模板的渲染逻辑**：模板内部（_tmplBottomWhite 等）不动，只动外层调用方式和 cardWidth 传递方式
4. **不改变导入按钮的位置**：顶部栏右上角保持不变
5. **保留 12 张/月限制**：`_monthPhotos.length` 不超过 12
6. **保留 RepaintBoundary 导出快照**：单张导出和 A4 导出的 key 机制不变
